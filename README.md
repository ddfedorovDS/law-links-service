# Law Links Service

Сервис на FastAPI, который находит в тексте ссылки на нормы права («пп. 1 п. 1 ст. 374 НК РФ») и возвращает их в структурированном виде: акт из базы `law_aliases.json`, статья, пункт или часть, подпункт. Условие задания — в [`TASK.md`](TASK.md).

## Быстрый старт (Docker)

```bash
# сборка образа
docker build -t law-links-service .

# запуск контейнера
docker run -d -p 8978:8978 --name law-links-container law-links-service

# проверка
curl -X POST "http://localhost:8978/detect" \
     -H "Content-Type: application/json" \
     -d '{"text": "Согласно статье 23 Налогового кодекса и ст. 145 Гражданского кодекса"}'
```

Ответ:

```json
{"links": [
  {"law_id": 15, "article": "23", "point_article": null, "subpoint_article": null},
  {"law_id": 5, "article": "145", "point_article": null, "subpoint_article": null}
]}
```

Интерфейс Swagger для ручной проверки: http://localhost:8978/docs. Состояние сервиса: `GET /health` → `{"status": "healthy"}`.

Остановка и удаление (в `TASK.md` команды обращаются к имени образа вместо имени контейнера, здесь исправлено):

```bash
docker stop law-links-container
docker rm law-links-container
docker rmi law-links-service
```

## Запуск без Docker

```bash
python -m venv .venv
.venv\Scripts\activate            # windows; на linux и mac: source .venv/bin/activate
pip install -r requirements.txt
python main.py                    # сервис на http://localhost:8978
```

Требуется Python 3.10 или новее (в образе используется 3.12).

## Как устроен алгоритм

Базовое решение — правила, без машинного обучения: размеченного корпуса для обучения нет, а формат ссылок сильно конвенциональный. Код в `extractor.py`, пять шагов:

1. **Нормализация.** Нижний регистр, `ё` → `е`, все виды кавычек и тире к одному виду, схлопывание пробелов (в том числе неразрывных), `N 152` и `№ 152` → `№152`, замена латинских букв-двойников в смешанных словах (в базе Семейный кодекс записан как `CК` с латинской C).
2. **Токенизация со стеммингом.** Слова приводятся к основе стеммером Snowball (`nltk`), чтобы «Налогового Кодекса» совпало с «Налоговый кодекс» из базы. Составные слова через дефис стеммятся по частям («Уголовно-процессуального»).
3. **Поиск актов.** Все варианты названий из базы (18 724 строки для 1055 актов) собираются в индекс при запуске сервиса. В тексте в каждой позиции ищется самое длинное совпадающее название. Название без типа акта (только `«О полиции»`) засчитывается, только если в тексте оно в кавычках. Если название относится к нескольким актам (например, «ФЗ №127-ФЗ»), ссылка не возвращается.
4. **Разбор цепочки слева от акта.** Регулярное выражение, прижатое к началу названия акта, разбирает уровни «подпункт → пункт или часть → статья». Учитываются словоформы маркеров («статье», «пунктом», «частью»), сокращения (`ст.`, `ст.ст.`, `п.`, `п.п.`, `пп.`, `подп.`, `ч.`), перечисления («4, 5, 6 и 8»), буквенные пункты («а», «"а"», «а)»), номера с точками и диапазоны («30.1», «43.2-6»), номера словами («части второй»). Между цепочкой и названием допускаются слова вроде «Закона», «Федерального закона от 27.07.2006 № 152-ФЗ». Несколько цепочек перед одним актом («п. 2 ст. 450 и статьёй 450.1 ГК РФ») разбираются все.
5. **Сборка ответа.** Перечисления раскрываются в отдельные ссылки (декартово произведение уровней): «в подпунктах а, б и с пункта 3.345, 23 в статье 66 НК РФ» → 6 ссылок.

Главный принцип: ссылка = цепочка + акт из базы, стоящий сразу после неё. Акт без цепочки ссылкой не считается. Это защищает от ложных срабатываний на названиях-обычных словах: в базе есть стандарты с названиями «Основные средства», «Доходы», «Аренда».

## Принятые решения

Задание не описывает часть ситуаций. Как мы их трактуем, записано в [`decisions.md`](decisions.md). Основное:

- акта нет в базе (Конституция, «рандомного кодекса», «ФЗ №20-456») — ссылку не возвращаем;
- нет статьи («п. 10 АПК») — `article: null`;
- перечисления раскрываем, диапазоны («43.2-6») оставляем одной строкой;
- часть записывается в `point_article`; если есть и пункт, и часть, в `point_article` идёт пункт;
- повторные упоминания сохраняются, порядок ссылок — как в тексте.

## Оценка качества

**Метрика.** Ссылка считается верной, только если совпали все четыре поля (`law_id`, `article`, `point_article`, `subpoint_article`). Ответ и эталон сравниваются как мультимножества; TP, FP, FN суммируются по всем текстам (микроусреднение); считаются precision, recall, F1. Отдельно считается качество поиска актов (только `law_id` в каждом тексте), чтобы отличать ошибки поиска закона от ошибок разбора цепочки. Accuracy не используется: множество «не-ссылок» в тексте не определено.

**Данные** (`data/`):

| Набор | Текстов | Ссылок | Назначение |
|---|---|---|---|
| `gold_dev.jsonl` | 28 | 34 | тестовый текст из задания по предложениям; на нём отлаживались правила |
| `gold_holdout.jsonl` | 37 | 41 | отложенная выборка: новые фразы, в том числе от участника команды |
| `gold_blind.jsonl` | 50 | 61 | слепая выборка: фразы от участника команды, не участвовавшего в написании правил и алгоритма; размечены до запуска алгоритма |

**Результаты** (подробно — в [`metrics.md`](metrics.md)):

| Набор | Precision | Recall | F1 |
|---|---|---|---|
| dev | 1.000 | 1.000 | 1.000 |
| holdout | 1.000 | 1.000 | 1.000 |
| **слепая выборка, первый прогон** | **0.939** | **0.754** | **0.836** |
| слепая выборка после исправлений | 1.000 | 0.902 | 0.948 |

Главная оценка качества — **F1 = 0.836** на слепой выборке при первом прогоне: под эти фразы ничего не подгонялось. Результаты на dev и holdout оптимистичны: правила писались по dev, а фразы holdout были прочитаны при уточнении правил разметки. Число после исправлений тоже оптимистично, потому что исправления делались по ошибкам на этой же выборке. Исправлялись только общие дефекты (названия через дефис, «п.п.», «стат.», буквы со скобкой), а не отдельные опечатки.

Оценка воспроизводится одной командой:

```bash
python evaluate.py                                           # dev, алгоритм напрямую
python evaluate.py --data data/gold_blind.jsonl              # слепая выборка
python evaluate.py --url http://localhost:8978/detect        # через работающий сервис или контейнер
python evaluate.py --check                                   # самопроверка оценщика
```

## Ограничения

- Битые и слипшиеся записи не распознаются: «ст.» без номера, «в соответствии сост. 309», «ст ст 393394».
- Название акта должно совпасть с одним из вариантов в базе с точностью до словоформ. Сокращённое или изменённое название («О Центральном банке Российской Федерации» вместо официального «…(Банке России)») не находится. Нечёткое сравнение названий сознательно не используется: в экспериментах оно давало ложные совпадения (например, «Конституция» сопоставлялась с посторонним указом).
- Ссылки, где акт стоит перед статьёй («ФЗ № 44-ФЗ, ст. 3-7»), не распознаются: по условию задания указатель пишется в обратном иерархическом порядке.
- Если есть и пункт, и часть («п. 6 ч. 1 ст. 81»), часть теряется: в схеме ответа для неё нет поля.
- Эталон размечен по правилам `decisions.md` с помощью LLM-ассистента и проверен вручную; согласие независимых разметчиков не оценивалось.
